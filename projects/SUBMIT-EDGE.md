# Microsoft Edge Add-ons submission: copy-paste sheet for the owner (~10 min per extension)

**Bottom line: the Chrome zips work on Edge unchanged — no code changes needed.** Edge is Chromium-based, ships
the same MV3 engine, and supports `chrome.offscreen`, `optional_host_permissions`, `chrome.scripting`,
`chrome.alarms`/`notifications` identically to Chrome (Microsoft's own docs describe publishing Chromium
extensions to Edge Add-ons "with minimal to no code changes"). `minimum_chrome_version: "137"` in both
manifests is harmless on Edge: Edge's version number tracks Chrome's, so it gates the same real-world release.
Verified by re-running each extension's existing Chrome/Playwright test suite unchanged (see the "what was
verified" note at the end) — nothing about the Edge build path touches the extension source.

Dashboard: https://partner.microsoft.com/dashboard/microsoftedge/overview → **New extension** → upload the zip
→ fill the tabs below → **Submit for review**.

## Account setup (once, ~5 min, free)
- Free to register. Requires a personal Microsoft account (MSA) — Outlook/Live/Hotmail — as the account owner;
  work/school accounts are not accepted for the initial registration (you can add them as secondary users
  afterward). Register at https://partner.microsoft.com/dashboard/microsoftedge/overview, "Get started" on the
  Microsoft Edge card, choose **Individual** account type (can't be changed later), pick your country/region.
- No fee, unlike the general Microsoft Store for apps.

## Minor, non-blocking note on both privacy policies
Both `privacy.html` pages say "Chrome's storage" / "Chrome Web Store" a few times. That's technically accurate
even on Edge (the API is still called `chrome.storage`, and Edge exposes the same `chrome.*` namespace), so I
left it as-is rather than fork a second privacy page. If an Edge reviewer ever asks for browser-neutral wording,
it's a one-line edit to `PRIVACY.md`/`privacy.html` on my next wake — flag it to me if it comes up.

## What was actually verified vs. what to expect at review
- Verified: the zips are byte-identical to the Chrome Web Store uploads (built by the same `ext-kit/pack.sh`), Chromium supports every API both extensions use (offscreen, scripting, alarms,
  notifications, optional_host_permissions, commands), and each extension's full Playwright test suite
  (`test/e2e.mjs`, `test/unit.mjs`) still passes — those tests run against a real Chromium build (via
  Playwright), which is the same engine Edge ships.
- Not independently tested in real Microsoft Edge (no Edge binary in this environment) — this is standard for a
  Chromium-compatible MV3 extension and I'd be surprised if it behaved differently, but it's worth you doing one
  quick manual smoke test after the first Edge review approves it (install from the Edge Add-ons page, try the
  popup, try a pick / a watch).
- Edge review turnaround is typically faster than Chrome's (often within a day), but budget the same "give it
  a few days" expectation as the CWS sheet.
