How to get an alert when exam results (or an admit card) are published

Boards rarely say exactly when a results or admit-card page will go live. Here's how to watch it without hammering the server or missing the moment.

Results day usually goes the same way: the page says "Result will be declared shortly" for hours, everyone keeps pressing refresh at the same time, and the site slows down or blocks visitors who reload too fast — sometimes right when the result actually appears. A watched page that alerts you, instead of you watching it yourself, avoids both problems.

1. Check whether the board already tells you

Before setting up anything, look for these on the official portal, since they're the most reliable option and add no load to the server:

  • An email or SMS alert opt-in in your registration or candidate account.
  • An official announcement channel (Twitter/X account, Telegram channel) some boards use to post the exact go-live time.
  • A scheduled date/time on the board's own notice board or press release, which tells you when to start watching instead of watching for days.

2. Pick a trigger word that won't false-fire

The placeholder text and the real result text are usually different enough to watch for directly:

  • Watch for a phrase to appear: "Result Declared", "Download Marksheet", "Admit Card Available", or a "Download" button label that isn't there yet.
  • Or watch for the placeholder to disappear: "not yet available", "will be updated soon", "link will be activated". This is often safer, since boards don't always agree on one exact wording for the result state, but almost always use a similar "not ready" message beforehand.
  • Avoid single common words like "result" or "available" on their own — they're often already on the page in a menu, a heading or an old notice.

3. Use a refresh interval that won't get you blocked

Government and university portals get their heaviest traffic of the year on results day, and many rate-limit or temporarily block visitors who reload too fast. Being blocked is worse than checking a minute later, because you may stay blocked after the result is out.

  • Once every 60 seconds is plenty for almost every results page. You will not meaningfully "lose" by checking once a minute instead of every few seconds.
  • Add a little randomness (a few seconds either way) if you're leaving it running for hours, so you're not reloading at the exact same instant as everyone else on the same timer.
  • If the site is visibly struggling (slow to load, error pages), lengthen your interval rather than shortening it. Reloading faster into a struggling server makes it slower for everyone, including you.

4. Set it up

Three ways, depending on how much you want to install:

  • Manually, with a reminder. Set an alarm for the announced date/time and check by hand every few minutes around it. Costs nothing, needs no tool, works fine if you have a rough idea of the timing.
  • A userscript (Tampermonkey/Violentmonkey), if you don't mind pasting a small script: 
    // ==UserScript==
// @name   Alert when result is declared
// @match  https://example-board.gov/result/*
// @grant  none
// ==/UserScript==
(() => {
  const TEXT = 'Result Declared';   // change to match your page
  const EVERY = 60;                 // seconds between reloads
  setTimeout(() => {
    if (document.body.innerText.includes(TEXT)) {
      document.title = 'RESULT OUT: ' + document.title;
      alert('Found "' + TEXT + '" — your result page is ready.');
    } else {
      setTimeout(() => location.reload(), EVERY * 1000);
    }
  }, 3000);
})();

5. Keep the computer awake and the tab open

None of the above works if the laptop sleeps or the browser is closed:

  • Windows: Settings → System → Power & battery → Screen and sleep, set "sleep" to Never while plugged in (put it back afterwards).
  • macOS: System Settings → Lock Screen → increase "Turn display off" and disable "Put hard disks to sleep", or run caffeinate in Terminal while you wait.
  • Keep the tab itself open and not discarded: browsers can unload background tabs to save memory after a long time, which stops a userscript running in it. An extension-based tool is less affected by this than a decade-old browser tab.

FAQ

How often should I refresh a results or admit-card page?

Once a minute is enough for almost every board's portal. Faster refreshing doesn't get you the result sooner in any meaningful way, and it raises the chance of being rate-limited or temporarily blocked.

Will auto-refreshing get my IP blocked?

It can, if you refresh too fast. Many exam-board sites apply rate limits or short-term blocks to visitors who reload aggressively, especially under the heavy load of results day. Sixty seconds or slower, with a little randomness, stays well clear of that.

Can a tool download my marksheet or admit card automatically?

No, and be wary of anything that claims to. Reload Until, like the userscript above, only watches the page and alerts you — it never clicks, logs in, downloads or submits a form on your behalf.

What if the results page needs me to be logged in?

A userscript or a browser extension uses your browser's existing session, so it works behind a login. A plain script that fetches the page over the network (with no browser) generally cannot, unless it also handles the login itself.

What if the site is down or very slow on results day?

That's common under heavy load right after a result is announced. Lengthen your refresh interval rather than shortening it, and try again in a few minutes. Hammering a struggling server slows it down further for everyone, including you.
