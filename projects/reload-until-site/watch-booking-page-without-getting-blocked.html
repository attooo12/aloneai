Watch a booking or appointment page for a free slot without getting rate-limited

Visa, passport, DMV, clinic, permit slots: the pages that release appointments in dribs and drabs are exactly the ones that block visitors who refresh too fast.

Popular booking systems get reloaded constantly by people hoping to catch a cancellation or a newly opened slot. Sites respond by rate-limiting, showing a CAPTCHA, or temporarily blocking clients that request the page too often. The unhelpful result: refreshing harder can get you specifically locked out right when a slot opens, while a slower, steadier check keeps working the whole time.

1. Look for an official waitlist or notify feature first

Many booking systems for visas, government services, driving tests and vaccination or clinic slots already have a "join waitlist", "notify me" or "email me when available" option, sometimes buried in an FAQ rather than on the booking page itself. If it exists, it does the watching for you with no risk of being blocked.

2. Watch for "no slots available" to disappear, not for a specific slot to appear

Available-slot pages tend to render very differently depending on what's open (a calendar, a dropdown, a list) which makes "a slot appeared" hard to match reliably. The unavailable state is usually one fixed phrase, which makes it the more reliable trigger:

  • Watch for phrases like "No appointments available", "Fully booked", "No slots" or "None available" to disappear.
  • If the page instead shows a fixed "Book now" button that's disabled when nothing is free, watch for it to become enabled, or watch for the disabled attribute/greyed-out class to go away.
  • Test your trigger against the current (unavailable) page first, so you know it matches before you start watching for hours.

3. Use an interval that won't get you blocked

There's no single safe number for every site, but a few rules hold up almost everywhere:

  • Once every 60–120 seconds is a reasonable default for pages that don't publish their own limits. Slots that open up rarely disappear again within a minute or two, so you lose very little by not checking every few seconds.
  • Add random jitter (say, ±10 seconds) instead of a perfectly fixed timer, especially if you expect many other people to be doing the same thing at the same moment.
  • Back off if you see errors, CAPTCHAs or a noticeably slower page. That's the site telling you it's under load or already suspicious of your traffic. Slow down, don't retry immediately.
  • Read the site's terms before automating anything. Some booking and ticketing systems explicitly forbid automated or scripted access in their terms of service, whatever tool is used to do it. If a site says so, refresh by hand instead.

4. Set up the watch

  • A userscript (Tampermonkey/Violentmonkey), watching for the negative text to disappear: 
    // ==UserScript==
// @name   Alert when a slot opens up
// @match  https://example-booking-site.com/appointments*
// @grant  none
// ==/UserScript==
(() => {
  const GONE = 'No appointments available';  // text that means "nothing free"
  const EVERY = 90;                          // seconds between reloads
  setTimeout(() => {
    if (!document.body.innerText.includes(GONE)) {
      document.title = 'SLOT OPEN: ' + document.title;
      alert('A slot may be available — go check and book it yourself.');
    } else {
      setTimeout(() => location.reload(), EVERY * 1000);
    }
  }, 3000);
})();

5. When it fires, book it yourself

Whatever tool you use, treat the alert as a signal to go look, not a green light to auto-submit anything. Reload Until, and the userscript above, only reload and read the page — they never fill in a form, click a booking button or make a purchase for you. Besides being the honest way to do it, most booking systems that ban automated clients are specifically watching for scripted booking, not for a page being reloaded and read.

FAQ

Is it against the rules to auto-refresh a booking page?

It depends on the site. Reloading a public page on a sensible interval (a minute or slower) is generally fine, but some booking and ticketing systems explicitly forbid any automated or scripted access in their terms, regardless of speed. Check the terms of the specific site, and refresh by hand if it says not to automate access.

What refresh interval is safe?

There's no universal number, but most sites' rate limits sit well above once a minute. Sixty to ninety seconds with a little randomness is a reasonable default that rarely trips a limit, while still catching a slot within a minute or two of it opening.

Should I let a script or extension book the slot automatically once it finds one?

No. Use monitoring tools only to watch and alert you, then complete the booking yourself. Auto-booking tools are more likely to violate a site's terms, and mistakes (wrong slot, wrong details) are harder to undo than a missed alert.

Why does the page still say "no appointments" when I've heard slots opened?

Some pages cache their availability for a short time, or the slot was taken between your reload and the next one. Watching for the "no appointments" phrase to disappear, rather than for a specific count, catches this as soon as the page itself updates.

Can I watch more than one booking page at the same time?

Reload Until's free tier watches one tab at a time; Pro removes that limit. A userscript can, in principle, run on several matching pages at once if you widen its @match, but you'll want a different trigger text for each site.
