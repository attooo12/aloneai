# Chrome Web Store Market Research — 2026-09-23

Method: fetched Chrome Web Store search results (`chromewebstore.google.com/search/<query>?hl=en`) and item
detail/reviews pages via `curl` (no JS rendering needed — ratings, install counts, "Updated" date and
"Offers in-app purchases" badge are all present in the static HTML). Sampled 1-2 top items' `/reviews` pages
per promising idea and pulled the raw review snippets to look for "stopped working", "broken", "predatory
subscription", "too many permissions" type complaints. Install counts from CWS are bucketed (e.g. "100,000"
means "100,000+"), so totals below are floors, not exact sums.

13 ideas were evaluated: the 10 given + 3 added from this recipe (recently-launched niche where all
incumbents are tiny/abandoned, or a flagship extension with visible 1-star "doesn't work"/"data loss"
complaints): **PDF merge/split/compress (local, no upload)**, **screenshot capture & annotate**, **tab/session
manager**.

## Ranked shortlist (top 3) + recommendation

**#1 — Auto refresh / conditional tab reloader ("reload until X happens")**
Best ratio of demand to effort: ~1.8M+ installs across the top 5 competitors, an already-proven
willingness to pay (3 of 5 top results monetize), the lowest build effort of any idea tested (1-2 days for
a solid MV3 v1), and the lowest permission footprint (`activeTab`, `alarms`, `storage` — no `<all_urls>`
needed if scoped to the active tab). The strongest incumbent by installs (Easy Auto Refresh, 1M users,
3.9★) has a visible ethics gap — reviewers flag a "predatory" subscription-cancellation flow and a paywall on
using more than one tab at a time — which is exactly the kind of thing an honest, clearly-priced freemium
extension can win reviews and word-of-mouth against.

*V1 feature list:*
- Per-tab refresh interval (seconds/minutes), with a visible on-page countdown badge.
- Free: fixed-interval reload on up to 2 tabs at once, manual pause/resume, random jitter to avoid
  hammering a server predictably.
- Paid ($3/mo or $15 lifetime): unlimited simultaneous tabs, conditional reload ("stop/alert when text
  X appears or disappears on the page", CSS-selector based), desktop/sound notification on trigger, and
  scheduled reload windows (e.g. "only reload 9am-5pm weekdays").
- No account, no server round-trip, no tracking — all state in `chrome.storage.local`.

**#2 — CSS colour picker + palette manager**
Largest raw addressable demand of anything tested (top 5 alone are 4.9M+ installs) and a documented,
currently-broken competitor (Hex Color Picker, 80k users, 2.9★, "doesn't work on most sites anymore") sitting
right next to a 2+-year-stale market leader (ColorZilla). Free tier: standard eyedropper + hex/RGB/HSL
copy, matching what's free everywhere today. Paid ($3/mo or $12 lifetime): persistent palette history/library
across sessions, one-click WCAG contrast checker, and export to CSS variables / Tailwind config / Figma
tokens — a real "prosumer" upgrade designers would pay for.

**#3 — Tab/session manager reliability rewrite**
1.1M+ combined demand and the clearest "stopped working, lost my data" complaint cluster found in this
whole study (100k-user incumbent at 3.5★ with crash/data-loss reviews). Higher effort (robust local storage +
`tabGroups` API) and higher permission surface than #1/#2, so it's a good #3 rather than the lead pick, but
the pain point is real and monetizable: free tier covers basic save/restore; paid tier adds scheduled
encrypted local backups (export to a file you control, no cloud account) and guaranteed tab-group restore.

**Recommendation:** build #1 (auto-refresh / conditional reloader) first — it is buildable in days, has the
lowest review/permission risk, and rides a demand curve that's already proven to convert to paid. Consider
#2 as the next extension only after #1 ships and gets initial review signal, since a colour-picker's
monetizable delta (palette management) is a slightly harder sell than "stop me from having to babysit a
refresh button."
